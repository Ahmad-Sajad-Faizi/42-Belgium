# 42-Belgium

My exercises and projects from the **42 Antwerp Piscine**—the intensive, month-long coding bootcamp that serves as the entry selection for 42's programming curriculum. Everything here was written in C (plus some Shell), following 42's strict coding standard (the **Norm**) and built without external libraries beyond what's explicitly allowed.

## Before you use this repo

**42's rules on academic integrity are serious, and they apply to you too if you're a 42 student.** Copying code from a public repo like this one—even if you rewrite it slightly— is considered cheating, and it can get you and the person who wrote it excluded from the school. If you're doing the Piscine or the curriculum, **please don't copy this code.**

The whole point of the Piscine is to struggle with these problems until the concepts actually click. If you paste a solution instead of writing your own, you skip the part that makes the exercise worth doing — you'll fall behind fast once the projects get harder and start building directly on what you were supposed to learn here.

Use this repo to:
- Check your own solution *after* you've already solved it, to compare approaches
- Get unstuck on the *idea* behind an exercise if you're truly lost, without lifting the implementation
- See what a finished, norm-compliant version of a project looks like for inspiration

Don't use it to copy-paste your way through the bootcamp.

## What's in here

| Folder | What it covers |
|---|---|
| `shell00`, `shell01` | Shell scripting basics — command line tools, permissions, scripting logic |
| `c00` – `c13` | Core C exercises, roughly increasing in difficulty — from basic syntax and functions up through pointers, recursion, and reimplementing standard library functions |
| `rush00` – `rush02` | Team "rush" projects — larger exercises done in pairs/groups under time pressure |
| `BSQ` | A standalone algorithmic project (finding the largest square of space in a grid) |

Each exercise folder generally contains the subject's source files, a `Makefile` where required, and my implementation.

## How to actually learn this stuff

If you're working through the 42 Piscine (Antwerp or otherwise) and want to get good at it rather than just get through it:

1. **Read the subject fully before writing any code.** Most mistakes come from misreading a constraint, not from not knowing C.
2. **Write your own solution first, even a bad one.** A working-but-ugly version teaches you more than reading someone else's clean one.
3. **Run it against edge cases yourself** — empty input, negative numbers, huge numbers, weird whitespace — before you trust it.
4. **Check the Norm yourself** (or with `norminette` if you're on a 42 machine) instead of relying on someone else's code as your reference for "how it's supposed to look."
5. **Ask your peers to explain concepts, not to hand you code.** Pair-debugging is how most people actually get through the Piscine.
6. Only look at a finished repo like this one **after** you've genuinely tried — to compare, not to copy.
